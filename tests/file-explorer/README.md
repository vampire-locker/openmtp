# 大目录界面回归验证

这组测试覆盖 OpenMTP 列表和网格的虚拟化、排序缓存、选择与导航，以及 MTP 批量目录读取。使用仓库现有依赖，不新增生产或测试依赖。

## 实现范围

- 列表使用上下占位行，网格使用完整高度容器和定位后的可见卡片；只挂载视口内条目及前后各 3 行缓冲。
- 列表行高 62px；网格卡片 100×137px。尺寸由 `app/containers/HomePage/utils/virtualWindow.js` 统一提供给样式和窗口计算。
- 滚动通过 `requestAnimationFrame` 合并更新；`ResizeObserver` 跟踪滚动区域尺寸。网格列数随可用宽度变化。
- 选择数组保持完整目录语义。`reselect` 按数组引用缓存 Set，渲染只对可见条目调用 `Set.has`，不再保存整目录 JSX 或逐条 `setState`。
- 排序按文件数组引用、方向、字段和目录优先设置缓存。单纯选择变化不重新排序。
- 键盘沿用原有列表上下、网格左右及 Shift 扩选逻辑；目标可以尚未挂载，通过完整排序数组的路径索引滚动到目标，并避开吸顶表头。
- 目录、排序和视图模式切换重置滚动；目录变更释放旧路径索引，卸载时清理监听器、observer 和待执行动画帧。

排序仍需处理整个目录，首次排序为 O(N log N)；选择集合构建为 O(S)，可见条目选择检查为 O(V)。排序后的选中边界查找不再嵌套遍历文件和选中数组，最坏为 O(N + S)。全选仍需 O(N)，完整目录数据也仍保留在内存中。

MTP 非递归目录读取优先使用 `GetObjectPropList`，分别请求父对象、文件名、格式、大小和修改日期，再按对象句柄合并。只返回目标目录的直接子项；保留隐藏文件过滤、64 位文件大小和原有路径语义。根目录或不支持批量属性的设备使用兼容读取。协议能力拒绝或完整但无效的数据集可回退；USB 超时不会在已失效的会话上继续读取，也不会发布部分目录作为成功结果。

目录读取阶段的 USB 等待上限为 120 秒，结束后恢复原设置；USB 文件字节读取仍沿用上游实现；下载遍历使用任务内索引，写入采用下述空间检查与临时文件提交。原生互斥锁覆盖完整导出调用，避免共享 USB 会话被并发使用。界面在读取时显示加载提示，并拦截重复目录打开和键盘操作。`Walk.async` 仍以 `recursive:false` 返回完整结果后交给界面。

## 运行

在项目根目录安装现有锁定依赖后执行：

```sh
yarn test:file-explorer
yarn test:file-explorer:browser
yarn lint
yarn build-no-verify
```

没有全局 Yarn 时，可先使用仓库的可执行文件目录：

```sh
export PATH="$PWD/node_modules/.bin:$PATH"
```

浏览器测试默认使用 macOS 的 Google Chrome，也可通过 `CHROME_BIN` 指定 Chromium 可执行文件。测试使用独立临时用户目录和调试管道，不连接日常浏览器会话；结束后删除临时目录。测试需要允许启动浏览器进程。

本次在 Node 22.23.2 上构建时，旧版 `file-loader`/`loader-utils` 使用的哈希算法需要兼容选项：

```sh
NODE_OPTIONS=--openssl-legacy-provider yarn build-no-verify
```

此选项仅用于本地构建命令，没有写入应用运行配置或更改依赖。

## 全选复制准备阶段修复与验证（2026-10-23）

此前截图中的 `Processing` 是总体进度预处理：原下载器在真正写入电脑之前，逐个解析每个源文件路径。路径解析会扫描父目录并逐个查询文件名，全选四万多个同目录文件会造成近似 O(N²) 的查找；关闭总体进度后仍有同样的路径解析问题。

修复后，每次下载建立独立的目录索引。同一父目录仅列举一次，多个选中项通过路径索引取回对象句柄，子目录利用已知句柄继续遍历。总体进度开启时先汇总索引中的大小，再调用原文件写入器；关闭时边遍历边调用原写入器。缓存不会跨任务或连接保留。上传路径不使用这个索引。

现有 `go-mtpx` 依赖通过本地补丁增加可注入遍历入口，未重写 USB 文件读取、覆盖规则和时间戳处理。另修复完成回调对底层错误的误判，去除下载进度回调的共享变量竞争，并让准备阶段明确显示尚未写入文件。

本轮新增验证：

- 1 万、5 万个同目录源文件，遍历回调覆盖全部条目，父目录读取次数均为 1。
- 嵌套目录使用已知对象句柄，隐藏文件/排除规则、断开连接、失效路径和任务缓存隔离。
- 总体进度开/关均可通过注入遍历驱动原目录写入器，不再调用旧的逐路径查找。
- JS 成功、底层完成回调返回错误、进度回调错误和 FFI 异常均正确分流；失败不触发完成回调。
- 真机通过新内核分别在总体进度开/关模式下载同样 3 个小于 128KiB 的 JPEG。每轮实际落盘 3 个文件，共 244,901 字节，全部 SHA-256 与手机原文件一致。两轮总耗时约 5.54 秒、5.60 秒；每轮日志只有一次 Camera 目录读取。
- 新增 Go/JS 测试、改动 JS lint、内核和主/渲染进程构建通过。已有虚拟化测试未重复执行。

真机测试只写入新建的临时目录，未覆盖备份，未修改手机文件。没有进行四万多个文件的全量复制、覆盖已有文件、超大文件或中途断线实测。小样本时间包含当时的缓存状态，不能用于推算整批备份耗时。后续安全保护将写入改为临时文件提交，具体行为见下节。

## 容量保护与停止复制（2026-10-26）

最终行为：

- 开始写入前检查整批去重后的文件大小和目标卷可用空间，预留 64 MiB。关闭总体进度显示仍执行容量预检；不预先扣除待覆盖文件的空间，因快照或克隆可能使覆盖不释放物理空间。
- 每个文件开始写入前再次检查，写入中每 8 MiB 或 1 秒检查剩余需求，避免其他进程消耗空间后仍继续写入。
- 当前文件先写入同目录的隐藏临时文件，校验长度、刷新并关闭后，才替换最终路径。取消、空间下降或读取失败时，不破坏旧目标文件；已完成的文件保留。
- 进度页提供 `Stop copying`，点击后显示 `Stopping…` 并禁用重复点击。停止请求按任务 ID 隔离，不等待 USB 操作锁；准备阶段和实际传输阶段都有取消检查。
- 取消需等待正在执行的路径解析/设备调用返回；目录属性请求的单次 USB 等待上限为 120 秒，不保证立即完成停止。中断后关闭 MTP 会话，需刷新手机连接。没有实现暂停、断点续传或上传取消。
- 强制结束进程/系统崩溃无法执行临时文件清理，仍可能留下 `.openmtp-*.part`，但不会把它作为完整目标文件提交。

本轮已通过：

- 模拟需要 401 GiB、仅剩 15 GiB，两种总体进度模式都在任何写入前拒绝。
- 模拟写入期间空间减少、取消、读取失败和长度不符，旧备份保持不变且临时文件清理；正常提交替换成功。
- 空间查询失败、64 MiB 预留、未创建目标目录的所属卷检查。
- 原生取消控制的提前取消、过期请求隔离及 USB 锁独立性；对应错误分类。
- JS 活跃任务取消、结束后不再取消、旧内核能力检测；成功/失败回调分流。
- 独立 Chrome 中测试停止按钮、停止中禁用、状态提示和不支持内核的隐藏行为。
- 实际编译库的 C ABI 取消入口与跨任务隔离测试，未调用 Initialize，不涉及手机读写。

没有为了此次安全验证重启用户的大批复制，也没有用真实磁盘写满来测试。真实传输中的中途取消与连接恢复尚未做真机验收；此前小样本内容哈希验证属于上一版下载路径，不能替代这次安全行为的真机验收。
